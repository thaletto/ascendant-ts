# Use an explicit, versioned Yoga rule set with structured evidence

Yoga evaluation uses one closed, explicitly assembled rule set whose provenance is `ascendant-yoga` version 1. Definitions are immutable and grouped by formation family. Each definition owns a stable ID, display name, aliases, classification, attributed-effect description, required Divisions, sources, and one evaluation strategy. Public consumers can inspect descriptors but cannot register executable definitions at runtime.

Common definitions use a declarative condition tree. Evaluating that tree produces the matching typed evidence tree, so a Yoga's chart-specific cause cannot drift from its presence test. A named pure evaluator remains available internally for exceptional future definitions. One immutable index over the supplied Chart calculation serves every selected definition, and Effect orchestrates atomic preflight plus ordered evaluation with concurrency four.

The first rule-set version follows the supplied [Astrotalk catalog](https://astrotalk.com/astrology-yoga) for pilot selection, order, names, classifications, and attributed effects. Formation semantics for all ten are reconciled with B. V. Raman's [Three Hundred Important Combinations](https://3.imimg.com/data3/DX/OE/MY-4022699/three-hundred-important-combinations.pdf), whose first ten entries are this pilot. In particular, the lunar-flanking rules also follow [Phaladeepika 6.5](https://www.siva.sh/phaladeepika/6/5): Sun is excluded, and Ascendant's modern implementation also excludes Rahu and Ketu because the selected classical seven-graha rule does not count them. Mercury, Jupiter, and Venus are the natural-benefic set used by Adhi and Vasumathi. These are deliberate rule-set decisions rather than accidental Python parity.

_Considered:_ Python-style decorators and a mutable import-time registry (rejected because inclusion and order become side effects), one Effect service per Yoga (rejected because the dependency graph would grow with the catalog), opaque prose evidence (rejected because applications could not audit absence or format causes themselves), and a public plugin registry (rejected because it would weaken rule-set provenance).
